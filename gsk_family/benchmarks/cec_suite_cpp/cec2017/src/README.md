# CEC2017 standalone C++ port

`cec2017_problem.cpp` is a standalone, modern C++20 port of the CEC2017
single-objective benchmark suite (F1..F30) implementing the
`gskcec::BenchmarkProblem` interface declared in
`benchmarks/cec_suite_cpp/cec_tools/include/gskcec/benchmark/cec2017.hpp`.

- Source of truth for all numerics:
  `historical source: CEC2017 competition cec17_func.cpp`
  (Jane Jing Liang, Dec. 20th 2017, MATLAB MEX evaluator).
- `cec17_func.cpp` in this directory is an identical provenance copy
  (SHA256 `bc78dae2...58ff227e`); it is never compiled. `readme.txt` keeps
  the original MEX rebuild notes.
- Supported: functions 1..30, dimensions 10/30/50/100, bounds
  `[-100, 100]^D`, optimum value `100 * function_id`, biases included.

## Design

The MEX globals (`OShift`, `M`, `SS`, `y`, `z`, `ini_flag`) become
per-instance RAII state (`std::vector`): the constructor loads
`M_<f>_D<D>.txt`, `shift_data_<f>.txt` and, for f11..f20/f29/f30,
`shuffle_data_<f>_D<D>.txt` from the `data_root` passed to
`gskcec::cec2017::make_problem` (all reads go through
`gskcec::load_values_file`; no cwd-relative paths). `evaluate()` is `const`
and uses mutable scratch buffers that stand in for the reference globals
`y`/`z`; a problem instance is therefore NOT thread-safe -- use one
instance per thread.

Formulas, constants (`INF = 1e99`, the reference `E`/`PI` literals,
`5.12/100`, `1000/100`, `2.048/100`, `0.5/100`, `600/100`, `5/100` shrink
rates), loop structure, summation order, hybrid partition arithmetic
(`G_nx[i] = ceil(Gp[i]*nx)`, remainder to the last block) and composition
sigma/lambda/bias tables are transcribed verbatim. Errors:
`std::invalid_argument` for unsupported function/dimension (and wrong
`evaluate` vector size), `std::runtime_error` naming the path for
missing/bad data files.

## Reference quirks preserved (deliberately NOT fixed)

1. `schaffer_F7_func` (F6, and inside hf04/hf10) computes from the global
   `y` buffer -- the shifted but UNROTATED vector -- so the rotation matrix
   never affects F6. In hybrid context (`s_flag == r_flag == 0`) `sr_func`
   does not write `y` at all, so Schaffer F7 consumes the leading entries
   of the hybrid's shuffled vector instead of its own sub-block.
2. `step_rastrigin_func` (F8): the non-continuity rounding loop operates on
   stale `y` and is then fully overwritten by `sr_func`; it has no
   observable effect (kept verbatim). F8 behaves as plain shifted-rotated
   Rastrigin.
3. F9 (Levy) uses `w = 1 + (z - 1)/4`, so `f(shift_vector) != 900`; the
   offset is `0.625 + (D - 1) * 0.0625 * (1 + 10 sin^2(0.75 pi + 1))`. The
   suite optimum 900 is attained at `x = shift + M^-1 * ones`, not at the
   shift vector.
4. The loader branches at `func >= 20` (not 21): for F20 the reference
   requests 10 rotation matrices and 10 line-wise shift rows, but
   `M_20_D<D>.txt` holds exactly `D*D` values and `shift_data_20.txt` a
   single 100-value line; the extra `fscanf` calls fail silently and the
   garbage tail is never used. The port loads only what is consumed
   (one matrix, first `D` shift values).
5. Composition shift data (f >= 21) is read line-wise: the first `D` values
   of each of 10 lines. Every shipped `shift_data_<f>.txt` line holds
   exactly 100 values, so the port indexes the flattened file as
   consecutive 100-value blocks (verified; a count check guards this).
6. F29/F30 load `10*D` shuffle indices but cf09/cf10 use only the first
   three `D`-rows. `bi_rastrigin_func` inside hf03 (F13) sign-flips with
   the leading entries of the FULL shift vector (`Os` base pointer), and
   with `s_flag == 0` copies a sub-view of `y` onto the start of `y`
   (non-overlapping for every supported dimension).
7. `sum_diff_pow_func` (F2) uses `abs(double)` (the C++ overload, i.e.
   `fabs`) and an int exponent promoted to double, matching the MEX build.
8. Dead reference code is not ported: `sphere_func`, `dif_powers_func`,
   `dixon_price_func`, `asyfunc`, `oszfunc` are never called by any
   CEC2017 function; `levy_func`'s unused `sum1` local is omitted.
9. D=2/D=20 are partially supported by the reference but excluded here per
   the integration contract (`supported_dimensions() = {10, 30, 50, 100}`).

## Validation

`benchmarks/cec_suite_cpp/cec_tools/tests/unit/cec2017_tests.cpp` checks metadata for all
30 x 4 problems, `f(shift) == bias` for f1/f3..f8/f10 (and the analytic F9
quirk value), error handling, and every row of
`benchmarks/cec_suite_cpp/cec_tools/tests/data/cec2017_expected.csv` -- 600 values
(30 functions x 4 dimensions x 5 probe points) generated by the original
reference MEX -- at relative tolerance 1e-10.

```
g++ -std=c++20 -O2 -Wall -Wextra -I benchmarks/cec_suite_cpp/cec_tools/include ^
    benchmarks/cec_suite_cpp/cec_tools/src/benchmark/data_loading.cpp ^
    benchmarks/cec_suite_cpp/cec2017/src/cec2017_problem.cpp ^
    benchmarks/cec_suite_cpp/cec_tools/tests/unit/cec2017_tests.cpp -o cec2017_tests.exe
cec2017_tests.exe <project_root>
```

Last run: 600/600 rows matched, max relative deviation 4.8e-15
(F2 D100, the pow-heavy worst case), 3921 checks passed.
